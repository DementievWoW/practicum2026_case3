# Q&A для подготовки к выступлению

500 вопросов с ответами (по 100 на тему). Используйте для подготовки к защите и QA-сессии: каждый прогоняет свой блок + общий по архитектуре.

| Файл | Тема | Ответственный |
|---|---|---|
| [00_architecture.md](00_architecture.md) | Архитектура и принцип модели (общая) | все 4 |
| [01_schema.md](01_schema.md) | Schema layer + фронтенд | Участник 1 |
| [02_generator.md](02_generator.md) | Генератор SQL + Reflection-loop | Участник 3 |
| [03_auditor.md](03_auditor.md) | Аудитор (Phase 1 + 1.5 + 2) | Участник 2 |
| [04_orchestrator.md](04_orchestrator.md) | Оркестратор + датасет + инфра | Участник 4 |

## Как готовиться (за вечер до выступления)
1. **Свой блок** прогнать целиком, отмечая вопросы, на которые ответ «не уверен».
2. **00_architecture.md** — общий, читают все: на защите его задают чаще всего.
3. **Топ-30 для своего блока** — пометить и проговорить вслух (там пересечения с реальным демо).
4. Соседский блок — пробежать «по диагонали»: знать, кто за что и куда отправить вопрос.

## Принцип формата
- Вопросы — те, что задаст придирчивый ментор / жюри / заказчик.
- Ответы короткие (1–3 строки), специфичные к нашей системе: Qwen2.5-Coder-32B, threshold 4.0, 60 таблиц, AWQ-4bit, FAISS top-15, и т.д. Без воды.
- Если ответ не очевиден из кода — он приведён точно с тем, что мы планируем сказать.

## Что нет смысла спрашивать «по бумажке»
- Точные имена методов/файлов — есть в репо.
- Названия моделей и порты — все в `.env.example` и `docker-compose.yml`.
- Конкретные правила — в `src/case3/audit/rules.py` (см. `target_components.png`).
