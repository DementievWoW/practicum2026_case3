# ADR-0006 — Dataset synthesis via SQL-to-Text back-translation

- **Status:** Accepted
- **Date:** 2026-05-18
- **Deciders:** project owner

## Context

ТЗ (`tusk`):

> Собрать или синтезировать датасет пар «описание задачи на естественном
> языке → SQL-запрос», включающий как эталонные безопасные примеры,
> так и запросы с типичными уязвимостями.

Дополнительный критерий (бонус **+10 баллов**):

> Авторский размеченный датасет. Команда подготовила собственный
> датасет с примерами уязвимостей (не менее 50 пар).

Ментор (`take1`):

> Датасет. Скорее всего, генерируем сами. Лайфхак от Тимура:
> SQL-to-Text проще, чем Text-to-SQL, поэтому удобно брать готовые SQL
> и просить LLM описать словами. Минимум 300 примеров.

Из `case_3.txt`:

> валидационного датасета «промпт → SQL → эталон», скорее всего, не
> дадут, и его придётся синтезировать самостоятельно (это даёт
> дополнительные баллы).

Из `research/05_peripheral.md`:

- **OmniSQL / SynSQL-2.5M (VLDB 2025)** — авторы прямо обосновывают:
  «SQL-to-Text более стабилен из-за гибкости естественного языка».
  Каждый пример = схема + SQL + NL + CoT.
- **SING-SQL** — complexity-controlled synthesis с LLM-as-judge
  валидацией и SQL repair.
- Промпт-паттерн: «объясни SQL пошагово, затем сформулируй короткий
  NL-вопрос пользователя».

## Decision

1. **Метод синтеза — двухконтурная back-translation**:

   ```
   ┌────────────────────────┐
   │ Step A: SQL seed pool   │
   │  - 200 «эталонных»      │
   │    SQL (написаны нами   │
   │    по schema_catalog)   │
   │  - 100 «уязвимых» SQL   │
   │    по 9 классам         │
   │    baseline (балансом)  │
   └─────────┬──────────────┘
             │
             ▼
   ┌────────────────────────┐
   │ Step B: SQL-to-Text     │
   │  LLM (Qwen-Coder 32B    │
   │  или GPT-4o-mini)       │
   │  получает SQL + DDL +   │
   │  пишет 2 NL-варианта    │
   │  + сложность (easy/med/ │
   │  hard) + CoT-rationale  │
   └─────────┬──────────────┘
             │
             ▼
   ┌────────────────────────┐
   │ Step C: validation      │
   │  - SQL парсится         │
   │    pglast → SYNTACTIC   │
   │  - SQL исполняется в    │
   │    sandbox без ошибок   │
   │    (только для SELECT)  │
   │  - NL-вопрос содержит   │
   │    упоминание ключевых  │
   │    сущностей из SQL     │
   │    (LLM-judge с low     │
   │    threshold)           │
   └─────────┬──────────────┘
             │
             ▼
   ┌────────────────────────┐
   │ Step D: human review    │
   │  спот-чек 20% выборки   │
   │  (один человек, ~2 ч)   │
   └────────────────────────┘
   ```

2. **Объёмы и состав** (целевые числа):

   | Класс | Кол-во | Источник SQL |
   |---|---|---|
   | Безопасные / эталонные | 200 | Ручная разработка по `data_model_sql/data_model.sql` |
   | `SELECT_STAR` | 10 | Ручные + автогенерация |
   | `DML_NO_WHERE` | 10 | Ручные |
   | `NO_PAGINATION` | 10 | Ручные |
   | `DIRECT_SENSITIVE` | 15 | Ручные (выборка из чувствительных колонок: `name__ru`, паспорт-подобные поля) |
   | `SQL_INJ_CLASSIC` | 15 | Адаптации из PortSwigger PG cheat sheet + sqlmap |
   | `SQL_INJ_UNION` | 10 | sqlmap `union_query.xml` адаптации |
   | `SQL_INJ_TIME` | 10 | `pg_sleep(...)` payloads |
   | `PRIV_ESCALATE` | 10 | `SECURITY DEFINER`-функции из примеров PG docs |
   | `PLPGSQL_UNSAFE` | 10 | `EXECUTE format() / \|\|` антипаттерны |
   | **Итого** | **300** | бонус +10 закрывается с запасом (≥ 50) |

   Дополнительно генерируем 2 NL-варианта на каждый SQL → **600
   обучающих пар + 300 SQL-seed** для eval-set.

3. **Train / Eval split**:

   - `train` (для few-shot RAG в ADR-0003): **240 SQL** (= 80%).
     Из них 480 NL-вариантов.
   - `eval` (для измерения Execution Accuracy и Recall судьи):
     **60 SQL** (= 20%). 120 NL-вариантов.
   - Стратификация по vuln_class и по difficulty (easy/med/hard).
   - Сплит фиксируется seed=42, версионируется в `data/splits/v1.json`.

4. **Промпт SQL-to-Text** (для Step B):

   ```
   Дана PostgreSQL-схема (только релевантные таблицы):
   {ddl_chunk_with_comments}

   Дан SQL-запрос:
   {sql}

   1. Опиши пошагово, что делает запрос (3-5 предложений).
   2. Сформулируй 2 разные NL-формулировки задачи для аналитика,
      которые бы привели к написанию этого SQL. Одна формулировка
      — короткая (1 предложение), другая — развернутая (с контекстом
      «зачем»).
   3. Оцени сложность: easy / medium / hard.
   4. Если SQL содержит антипаттерн или уязвимость — кратко напиши,
      какой класс из списка: [SELECT_STAR, DML_NO_WHERE, NO_PAGINATION,
      DIRECT_SENSITIVE, SQL_INJ_CLASSIC, SQL_INJ_UNION, SQL_INJ_TIME,
      PRIV_ESCALATE, PLPGSQL_UNSAFE]. Если безопасен — "safe".

   Верни JSON: {
     "step_by_step": "...",
     "nl_short": "...",
     "nl_long": "...",
     "difficulty": "easy"|"medium"|"hard",
     "vuln_class": "..." | "safe"
   }
   ```

5. **Хранение датасета** — JSONL по 1 примеру в строке:
   `data/dataset_v1.jsonl`:

   ```json
   {
     "id": "case3-001",
     "sql": "...",
     "nl_short": "...",
     "nl_long": "...",
     "difficulty": "medium",
     "vuln_class": "DML_NO_WHERE" | "safe",
     "step_by_step": "...",
     "tables_used": ["acc_number", "sys_obj_type"],
     "split": "train" | "eval",
     "source": "manual" | "portswigger" | "sqlmap" | "pg-docs",
     "version": "v1"
   }
   ```

6. **Quality gate** перед merge в `master`:
   - 100 % примеров парсятся `pglast.parse_sql` без ошибок (либо
     `parse_plpgsql` для PL/pgSQL).
   - 100 % безопасных SELECT исполняются в sandbox без ошибок и
     возвращают ≥ 0 строк.
   - 100 % примеров с `vuln_class != "safe"` детектируются хотя бы
     одним правилом Phase 1 (ADR-0004) — это sanity-check, что
     правила и датасет согласованы.

7. **Не используем готовые корпуса BIRD/Spider/KaggleDBQA как
   train.** Они на других схемах, и наш генератор должен изучать
   именно домен GreenData. Используем только промпт-структуру оттуда.

## Consequences

**Положительные**

- Закрывает базовое требование «синтезировать датасет» + бонус
  «авторский датасет ≥ 50 пар».
- 300 SQL × 2 NL = 600 пар покрывают чек-лист «минимум 300»
  ментора.
- Размеченный по vuln_class датасет даёт нам метрику Recall судьи
  по классам (ADR-0007).
- Часть «уязвимых» SQL берётся из PortSwigger/sqlmap — это
  легитимные, общеизвестные payloads, без юридических рисков.

**Отрицательные / Риски**

- Back-translation качественнее ручного, но всё ещё может дать
  «слишком ровный» русский (одинаковый стиль вопросов). Митигируем:
  две формулировки на пример (short/long) + 20% human review.
- LLM может ошибиться в `vuln_class` метке. Митигируем: правило
  «Phase 1 должен подтвердить класс» в quality-gate; если правило
  не подтверждает — пример идёт в ручной review-список.
- Демо-схема `data_model.sql` сложна (60 таблиц, технические имена)
  — генерировать «эталонные» SQL руками медленно. План: 200 SQL × ~3
  мин = ~10 ч работы одного человека. По ролям из ТЗ это «подготовка
  данных», как и заявлено.
- ПДн в schema-комментариях — низкий риск, но не нулевой. Не
  заливаем seed SQL и NL в публичный репозиторий без проверки
  (см. ADR-0001: `data/` в `.gitignore` по умолчанию).

## Alternatives considered

| Альтернатива | Почему отказались |
|---|---|
| Чистый Text-to-SQL: писать NL и просить LLM сгенерировать SQL | Ментор: «SQL-to-Text проще». Качество NL у LLM выше, чем качество синтезированного SQL без проверки исполнением. |
| Использовать существующие датасеты (BIRD, Spider, KaggleDBQA) как train | На других схемах; не учат генератор именно нашему домену GreenData. Полезны только как структурный референс. |
| Сгенерировать 2.5M примеров (как OmniSQL/SynSQL-2.5M) | Избыточно для MVP; ресурс на одно-двое суток generation+QA — не окупается на хакатоне. 300 — ровно та точка, после которой возврат за пример падает. |
| Делать только безопасные SQL (без уязвимостей) | Тогда не на чем измерять Recall судьи; теряем бонус +10 за датасет с уязвимостями. |
| Брать payloads sqlmap «как есть» без адаптации к schema | Payloads под `users.password` — у нас нет такой колонки. Без адаптации судье будет «слишком легко». |
| Полностью ручная разметка 300 пар | 30-50 часов работы одного человека. Дороже и не лучше по качеству. |
| Закупить разметку на платформах (Toloka и т. п.) | Платно, NDA-вопросы, медленнее. |
