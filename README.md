**SQL Judge MVP**

Проект реализует минимальную систему автоматической проверки и исправления SQL-запросов.
Система анализирует запрос, находит потенциальные проблемы безопасности, оценивает уровень риска и пытается автоматически исправить запрос.

Основная цель проекта - показать цикл работы “проверка - оценка - исправление - повторная проверка”.

*Как работает система*

Система состоит из нескольких этапов:

1. Получение SQL-запроса
2. Проверка запроса набором правил
3. Формирование списка найденных проблем
4. Оценка уровня риска
5. Принятие решения: безопасен запрос или нет
6. При наличии проблем - автоматическое исправление запроса
7. Повторная проверка исправленного запроса

Цикл повторяется несколько раз до достижения безопасного состояния или достижения лимита итераций.

*Архитектура*

Система разделена на несколько модулей:

1. модуль правил (src/rules)

Содержит набор независимых проверок SQL-запросов.
Каждое правило проверяет отдельный тип проблемы (например: отсутствие ограничения, потенциальная утечка данных, опасные конструкции).

2. модуль проверки (src/judge)

Отвечает за запуск правил и сбор результатов.

judge_agent.py — основной вход в систему проверки
pipeline.py — объединение результатов правил и расчёт риска
models.py — структуры данных
recommendations.py — текстовые рекомендации по ошибкам

3. модуль исправления (src/fixer)

Отвечает за автоматическое исправление SQL-запросов на основе найденных проблем.

4. цикл выполнения (test_loop.py)

Оркестрирует процесс:

отправляет запрос на проверку
получает результат
вызывает исправление
повторяет процесс до завершения
Пример работы

В систему подаётся SQL-запрос:

SELECT * FROM credit_contract WHERE id = ' + user_input + '

Система может обнаружить:

использование SELECT *
потенциальную SQL-инъекцию
отсутствие ограничения количества строк

После этого запрос будет исправлен, например:

SELECT id FROM credit_contract WHERE id = $1 LIMIT 1000

*Что реализовано*

- набор правил проверки SQL
- агрегатор результатов проверок
- расчет уровня риска
- автоматическое исправление запросов
- цикл проверки и исправления

Ограничения текущей версии

- правила основаны на простом анализе текста
- исправления выполняются через простую замену строк
- нет анализа структуры SQL-запросов
- отсутствует модуль объяснения найденных проблем
- возможны повторные или нестабильные исправления

Направления улучшения
- переход от текстовых правил к структурному анализу SQL
- улучшение оценки риска с учётом контекста
- более устойчивый модуль исправления
- добавление слоя объяснения проблем на естественном языке
- предотвращение зацикливания исправлений
