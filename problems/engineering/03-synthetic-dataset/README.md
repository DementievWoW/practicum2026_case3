# 03 — Синтез датасета без эталона

## Что

Без размеченного датасета `(NL → SQL, vuln_class)` мы:
- **Не можем измерить Execution Accuracy** (нечего сравнивать с pred).
- **Не можем измерить Recall судьи** (нет ground-truth уязвимостей).
- **Не можем настроить few-shot** для генератора (нечего показывать как «пример»).

ТЗ (`tusk`) предполагает, что мы соберём датасет сами:
> Собрать или синтезировать датасет пар «описание задачи на естественном языке → SQL-запрос», включающий как эталонные безопасные примеры, так и запросы с типичными уязвимостями.

И отдельным **бонусом +10 баллов**:
> Авторский размеченный датасет. Команда подготовила собственный датасет с примерами уязвимостей (не менее 50 пар).

Менторский совет из `take1`:
> Лайфхак: SQL-to-Text проще, чем Text-to-SQL. Минимум 300 примеров.

## Почему критично

Прямой эффект на **15 баллов** EX + **15 баллов** аналитики + **10 баллов** бонуса = до **40 баллов**. Это и есть «инфраструктура победы»: без хорошего датасета все архитектурные решения остаются на бумаге.

Из обзора (`research/05_peripheral.md` § 1):
- **OmniSQL/SynSQL-2.5M** (VLDB 2025) построен на back-translation, 2.5M примеров.
- **SING-SQL** — то же, с complexity-controlled synthesis.
- Авторы прямо: «SQL-to-Text более стабилен из-за гибкости естественного языка».

## Силы, тянущие в разные стороны

| Куда тянет | Аргумент |
|---|---|
| **Ручная разметка** | Качество выше |
| **LLM-синтез** | Скорость, доменное разнообразие |
| **Брать готовые корпуса (BIRD/Spider)** | Уже размечено |
| **Собирать на нашей схеме** | Релевантность домену GreenData |
| **Много примеров (1000+)** | Лучше few-shot, лучше EX |
| **Мало примеров (300)** | Дешевле, быстрее, ментор дал ровно эту цифру |
| **Только безопасные SQL** | Простой baseline для EX |
| **С уязвимостями** | Тестируем судью + бонус +10 |
